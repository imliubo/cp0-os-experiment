# Store 内容对象垃圾回收

<!-- doc-locale: zh-CN -->
> [English](STORE-OBJECT-GC.md) | **简体中文**

`cp0-store-object-gc` 从本地内容寻址引用后端移除不可达的上传片段和中断的临时文件。它不收集发布者版本、设备缓存或应用程序包，并且不是复制的生产对象存储的替代品。

## 安全合同

- 没有参数表示`--dry-run`；删除需要显式的`--apply`标志；
- apply模式拒绝低于86,400秒的最小年龄；
- 对象根必须已经在绝对路径上存在，并且具有实际的`chunks`和`temporary`目录，这些目录不允许组或其他方访问；干运行从不创建或更改它们的权限，也从不运行数据库迁移。
- 分块前缀、文件名、校验和、临时名称、普通文件类型、inode、大小、链接计数和修改时间在任何删除之前都会被验证；
- 一个意外的文件、目录、符号链接、路径逃逸，或者inode或库存超过一百万文件的完整运行关闭失败；
- 在追加只读的 `submission_upload_chunks` 中引用的行始终会被保留；
- 未引用的分片和修改时间短于配置宽限期的临时文件会被保留；
- 成功的删除操作会 fsync 包含每个对象的目录。

上传操作会在写入对象之前立即获取一个共享的 PostgreSQL 事务提示锁，并在整个数据库提交过程中保持该锁。GC 扫描文件系统，然后在获取匹配的排它锁之前解决引用、重新验证候选项并删除它们。并发上传可以一起进行；GC 或者观察到它们提交的引用，或者在它们写入之前完成。中断的提交可以安全地重新运行，因为对象名称是不可变的，而且在持有排它锁时每个删除操作都独立证明了其不可达性。

## 操作

使用控制服务相同的私有数据库和对象根。在应用之前审查有符号整数 JSON 报告：

```sh
CP0_STORE_DATABASE_URL=postgres://... \
CP0_STORE_OBJECT_ROOT=/var/lib/cardputerzero-store/objects \
cargo run -p cp0-store-control-server --bin cp0-store-object-gc

CP0_STORE_DATABASE_URL=postgres://... \
CP0_STORE_OBJECT_ROOT=/var/lib/cardputerzero-store/objects \
cargo run -p cp0-store-control-server --bin cp0-store-object-gc -- --apply
```

`--minimum-age-seconds N` 可以在干运行时检查更短的时间间隔，或者增加默认的 24 小时宽限期。应用模式不能减少它。报告包括数据库观察时间以及聚合计数和字节；它不会打印对象内容、开发者身份、令牌或数据库凭证。模式迁移必须在运行此单独维护命令之前部署。

## 验证

PostgreSQL 17 接收测试创建引用的、孤儿的、年轻的和临时的对象。它证明了干运行不会做任何更改，年龄门限保留新文件，应用仅移除不可达文件，引用的内容保持可读，并且符号链接条目防止该运行中的所有删除。迁移 23 添加了用于有界 512 个对象引用批次的摘要索引。

生产复制、保留策略审批、删除证据保留，多区域生命周期规则和恢复协调仍为外部基础设施关卡。

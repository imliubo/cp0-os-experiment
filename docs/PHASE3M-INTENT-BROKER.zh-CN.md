# Phase 3M: 隔离意图代理

<!-- doc-locale: zh-CN -->
> [English](PHASE3M-INTENT-BROKER.md) | **简体中文**

应用程序不会接收任意的跨进程套接字或目标路径。
应用程序间的移交由 appd 通过有界、清单声明的动作和已认证的 Runtime 能力代理服务连接进行路由。

## 合同

应用程序清单可以导出多达八个意图动作。每个动作是一个最多包含96个ASCII字节的小写反向域名。发送者只能提供一个动作和最多1024个负载字节；它不能选择应用程序ID、套接字或进程。

appd 扫描根拥有的清单以查找请求的操作。没有匹配的接收器返回 `not-found`，而超过一个接收器返回 `ambiguous`；appd 从不默默地选择一个。全局内存队列最多包含八个消息。队列中的消息绑定到解析的应用程序ID，并且只能通过该应用程序的认证 `take` 调用移除一次。

意图接收是一个导出的应用程序入口点而不是用户权限。发送和接收仍然需要调用者的已安装UID、运行中的PID、精确的systemd cgroup和当前根拥有的manifest匹配。

## 单前台切换

排序是故意固定的：

1. appd 验证发送者、操作、唯一接收者和队列容量；
2. appd 将目标绑定的消息排队；
3. appd 将 `intent-accepted` 写入发送者的连接代理套接字；
4. 如果写入失败，appd 取消队列中的确切消息。
5. 只有在成功写入之后，appd 才会停止发送者并启动接收者；
6. 新的接收器实例调用`take`，该调用会一次性消费消息。

这保持了单前台应用不变量。若接收方在确认后的启动失败，有界消息会继续留在队列中，
以便后续通过可信 Launcher 启动时恢复；appd 记录转换失败，但不会再启动另一个应用。

## SDK和验证

Rust 暴露了 `intents::send` 和 `intents::take`。独立的 C/C++ 头文件和 WIT 合约暴露了相同的行为/负载模型。运行时宿主调用在使用唯一的代理 Unix 套接字之前会重复所有线性内存、行为和负载边界。

你好，Card导出`dev.cardputerzero.hello.open`. 按下`I`将该操作发送给自己；appd确认并重新启动它，新的实例将携带`restart`负载。主机测试涵盖清单验证、标准代理框架、模糊路由、队列耗尽、取消和一次性目标绑定交付。物理键驱动的过渡延迟，直到完成活跃的24小时稳定性运行。

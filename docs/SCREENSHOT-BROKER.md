# Trusted Screenshot Broker

## Contract

`Fn+J` is owned by the compositor and never reaches an application as a raw
PrintScreen key. The compositor sends the trusted action to the registered
System Shell without changing the current layer layout. The Shell then asks
Weston for one framebuffer capture and saves one PNG.

The V0.6 contract is intentionally fixed:

- exactly one 320x170 output;
- XRGB8888 or ARGB8888 shared-memory input;
- RGB PNG output;
- `/var/lib/cardputerzero/screenshots` is the only destination;
- filenames are generated by the Shell and cannot be supplied over IPC;
- at most 32 completed screenshots are retained.

No screenshot API is part of the application SDK. Applications cannot request
a device screenshot, name a destination, or read the screenshot directory.

## Authorization

Weston's capture global is present for protocol discovery, but capture is
denied by default. `cardputerzero-policy.so` installs an authority which grants
an attempt only when all of these conditions hold:

1. the trusted Shell has registered its `os.cardputerzero.shell` surface;
2. the capture request comes from that exact Wayland client connection;
3. the selected output is exactly 320x170.

Every other attempt is explicitly denied. This remains effective if another
Weston component accidentally adds a permissive screenshot authority, because
one denial overrides an authorization.

## Storage boundary

systemd creates the state directory with mode `0750` for `cp0-shell` while the
service retains `ProtectSystem=strict`. The writer refuses relative paths,
symlinked directories, directories owned by another UID, and group/world
writable directories.

Each PNG is written to a mode `0600` temporary file, flushed and fsynced, then
published with a non-overwriting hard link. A failed write is never exposed as
a completed screenshot. Retention scans at most 256 generated names and removes
the oldest names until 32 remain.

## User-visible lifecycle

The capture begins without showing an overlay, so the result contains the
screen that was visible when the key was pressed. After capture and durable
storage finish, the Shell shows `SCREENSHOT / SAVED` for two seconds. Protocol,
format, storage and authorization failures show `FAILED`; a missing capture
global or unsupported output contract shows `UNAVAILABLE`.

A second key press while capture is pending is ignored. The first capture is
not contaminated with a busy overlay and only one framebuffer-sized allocation
can exist at a time.

## Verification status

Local tests cover PNG dimensions, invalid pixel counts, insecure directories,
symlink destinations, generated names and the 32-file retention limit. The
compositor profile checks the exact-client authorization and image integration.
ARM64 build verification proves the pinned Weston 14 protocol and policy link
together. Physical `Fn+J`, LCD contents, SD write latency and retained-file
inspection remain device acceptance items.

# CardputerZero OS v0.1.0-rc.1

This is the republished release-candidate body for CardputerZero V0.6. The
older body is retained in `v0.1.0-rc.1.md` as an archive. This release is an
engineering candidate, not a production-certified firmware release.

## Highlights

- A minimal Debian/systemd OS for the Raspberry Pi CM0 with 512 MB RAM and a
  320x170 LCD, using a keyboard-first System Shell instead of a full desktop.
- A trusted compositor and single-foreground application model with Home,
  Apps, Tasks, Settings, Store, power, sleep, and recovery flows.
- WebAssembly application runtime isolation with per-app identities, cgroups,
  namespaces, seccomp, private storage, typed capability brokers, and owner
  permission decisions.
- SDK 1.1, WIT ABI contracts, Rust and C/C++ bindings, a PC simulator, the
  `cp0ctl` workflow, example applications, and the relocatable App DevKit.
- Signed `.capp` packages, Developer Mode deployment, Store verification and
  rollback foundations, immutable-root/data-partition groundwork, and recovery
  tooling.
- Stable release-image naming and an ARM64-native image build path so the
  published artifact name is independent of pi-gen's date prefix.

## Release Assets

- `cardputerzero-os-v0.1.0-rc.1-cp0-os-production.img.xz`: production-access
  image for CardputerZero V0.6.
- `cardputerzero-os-v0.1.0-rc.1-cp0-os-production.info`: build and image
  profile metadata.
- `SHA256SUMS`: SHA-256 manifest for the compressed image.
- `cardputerzero-app-devkit-*-aarch64-unknown-linux-gnu.tar.xz` and its
  `.sha256` file: relocatable Linux App DevKit archive.
- `cardputerzero-build-app.tar.xz` and its `.sha256` file: standalone app-build
  Skill archive.

The DevKit archive contains the Apache-2.0 license, third-party notices, SDK,
simulator, schemas, examples, and developer documentation.

## Verify Before Use

Run the checks from a directory containing the downloaded assets:

```sh
sha256sum -c SHA256SUMS
sha256sum -c cardputerzero-app-devkit-*-aarch64-unknown-linux-gnu.tar.xz.sha256
sha256sum -c cardputerzero-build-app.tar.xz.sha256
```

Inspect the `.info` file and keep the original checksum files with any image
backup. Flash the image only to disposable media until the hardware gates below
are closed.

## Access and Security Defaults

The image uses the `production` access profile. It contains no shared login
password or preinstalled SSH key. SSH and the unrestricted Owner SSH Shell are
off by default. The owner may physically enable Developer Mode, pair a
computer, and authorize signed SDK Apps through the constrained deployment
channel; this does not grant Bash, root, sudo, or ambient device access.

Developer Mode and the independent Owner SSH Shell are separate controls.
Recovery access requires a separately built recovery image and a physical boot
ceremony. The shared Linux kernel means app isolation is defense in depth, not a
mathematical claim of absolute isolation.

## Release-Candidate Status

This candidate has host build, image-profile, package, SDK, and application
runtime checks, but it is not a production acceptance sign-off. Before fleet or
long-term deployment, complete the V0.6 physical-device checks for cold boot,
LCD orientation and color, camera/audio behavior, access-profile defaults,
reboot and power-loss recovery, immutable-root/data persistence, Store
operations, performance, and the 24-hour stability and SD-write limits.
The authoritative status and acceptance evidence are tracked in
[`docs/ROADMAP.md`](../ROADMAP.md) and its linked phase documents.

## Source and Reproducibility

The release is built from the immutable Git tag by the pinned release workflow
with Rust 1.85.1 and the repository's pinned BSP/runtime inputs. Do not treat a
filename, a network address, or a passing host test as a substitute for the
authenticated checksum and physical-device acceptance.

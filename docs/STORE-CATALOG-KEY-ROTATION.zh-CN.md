# Store Catalog 密钥轮换

<!-- doc-locale: zh-CN -->
> [English](STORE-CATALOG-KEY-ROTATION.md) | **简体中文**

此运行手册定义了旋转Store Catalog签名密钥的工程边界。它并不声称存在生产HSM、操作员共识、CDN或舰队编排服务。

## 信任模型

`cp0-stored` 通过精确的小写SHA-256选择一个根拥有的公钥
`key_id` 包含在签名的目录中。目录不能添加或删除一个受信任的公钥。信任根的更改必须通过单独签名的OS更新或镜像到达。浏览器门户、控制平面和公共CDN不能修改此目录。

设备信任目录在有限重叠期间可能包含旧的和新的公钥。每个目录和碎片生成仍然由恰好一个公钥签名，并且公钥变更后目录序列单调性继续保持。

## 计划旋转

1. 在生产签名边界内生成新密钥。将其算法、公钥、`key_id`、保管人和激活窗口记录在审核仪式记录中。绝不要导出私钥。
2. 生成一个带有`<new-key-id>.pub`而不移除`<old-key-id>.pub`的签名OS信任更新。在 Canary 设备上验证根所有权、模式、精确32字节长度和文件名到密钥摘要绑定。
3. 继续使用旧密钥发布，直到信任更新达到所需的舰队阈值并回滚组。最后一个旧密钥目录必须在文档中规定的离线宽限期期间保持有效。
4. 发布下一个严格更高的目录序列并附上新键。在推广前验证生成、透明检查点、CDN字节和 Canary 刷新。在回退时绝不能重用一个序列。
5. 在所有受支持设备都拥有新密钥并且每个旧密钥目录库都过期后，发送另一个带签名的OS信任更新，以移除旧的公钥。在同一个更新中重启`cp0-stored`，以便其缓存的目录库在服务或授权安装之前重新验证信任根。
6. 保留公共记录、仪式证据和旧签名。根据HSM政策退役或销毁旧私钥；不要删除目录、包、审计或透明度历史。

一个离线设备如果错过了重叠部分，不能信任一个新的密钥目录。它必须首先接收一个包含新公钥的签名操作系统更新。目录或CDN内容永远不能作为可接受的信任启动。

## 紧急撤销

妥协响应是一个签名的OS安全更新，它会移除受影响的公钥，重启`cp0-stored`，并在可用时安装一个未被妥协的替换公钥。在该更新安装之前，已运行的设备可以通过其签名的有效窗口在内存中保留一个旧的验证目录；仅发布更高的序列号不是撤销。

事件操作员必须保留最后一个已知良好的数据库、不可变生成对象、透明前缀、HSM审核和CDN请求证据。恢复较早的数据库或Catalog序列是禁止的。如果没有可信任的密钥，Store刷新和安装将失败，而本地安装的应用将继续运行。

## 验证

```sh
cargo test -p cp0-stored catalog_key_rotation_requires_overlap
cargo test -p cp0-store-protocol -p cp0-store-publisher
cargo clippy -p cp0-stored --all-targets -- -D warnings
```

旋转测试从旧密钥目录开始，添加新公钥，重叠期间接受更高版本的新密钥目录，移除旧公钥，重启服务模型并拒绝更高版本的旧密钥目录而不替换缓存的新密钥生成。

量产完成还需要 HSM 支持的两人仪式，
签名 OS 信任更新，一个代表性的离线设备组，
CDN 推广和回滚练习，以及独立审核最终证据。

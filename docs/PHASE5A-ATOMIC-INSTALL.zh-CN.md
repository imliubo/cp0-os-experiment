# 第5A阶段：受信任的安装、升级和回滚

<!-- doc-locale: zh-CN -->
> [English](PHASE5A-ATOMIC-INSTALL.md) | **简体中文**

## 设备信任策略

生产安装需要有效的开发者签名和有效的商店签名。商店公钥是原始的32字节Ed25519密钥，安装为：

```text
/etc/cardputerzero/trust/store/<sha256-of-key>.pub
```

`image/build-image.sh` 可接受一个可选的 `CP0_STORE_PUBLIC_KEY` 路径，验证其确切长度并仅安装公钥。签名密钥从未进入镜像构建上下文。

撤销开发人员身份或商店身份将拒绝整个包。根拥有的标记由键 ID 命名，放置如下：

```text
/etc/cardputerzero/trust/revoked/<sha256-of-key>
```

一个没有商店签名的包除非满足以下所有条件才会被拒绝：

- `/etc/cardputerzero/developer-mode` 是一个包含恰好`enabled\n`的secure regular文件。
- 嵌入式开发密钥与下面的根拥有的文件匹配
  `/etc/cardputerzero/trust/developers`;
- 两个密钥ID都没有被撤销。

信任目录和文件必须不是链接，并且不能被组或其他用户写入。生产检查还需要 UID 0 所有者。

## 交易模型

`cp0ctl install` 在本地验证容器，以`0600`模式将其复制到根用户唯一的`/run/cardputerzero-appd`收件箱，并仅通过生命周期套接字发送生成的基本名称。appd 拒绝分隔符、`..`、隐藏名称、过长名称和非`.capp`文件。Shell 仍然受信任用于启动和UI操作，但安装和回滚命令还需要同伴UID 0。

appd 按照以下顺序进行安装：

1. 验证源类型、所有权/模式、包边界和规范编码；
2. 验证开发人员撤销/签名并存储或开发者模式信任；
3. 验证清单文件、设备SDK兼容性和打包的入口点；
4. 将每个常规文件以创建新文件的语义写入私有暂存目录，并使用`fsync`将其写入。
5. 将完整版本目录重命名并移动到同一文件系统及其父目录上；`fsync`
6. 验证预分配的稳定Unix账户，并原子性替换根拥有的应用程序注册表。

在步骤5之前断电会导致没有可见版本。在步骤5和6之间断电会导致一个无效的孤儿；重新尝试相同的带符号包会识别其精确文件并完成注册表激活。相同的ID/版本的现有内容永远不会被覆盖。注册表本身通过单独同步的临时文件和目录重命名进行更新。

## 稳定的标识和回滚

该镜像预分配了64个锁定的应用账户，从`cp0-app-20000`到`cp0-app-20063`。appd不能修改`/etc/passwd`，并且一个注册表身份永远不会被回收用于不同的应用ID。这限制了安装的应用程序数量，同时保持账户内存和磁盘开销微乎其微。

升级保留注册历史中的两个最近版本，并保留其不可变的包目录。`cp0ctl app rollback <app-id>`需要停止应用程序，验证之前的清单，并原子地切换活动注册版本。之前的当前版本成为下一个回滚目标，允许受控的向前回滚。

自动化测试覆盖了签名信任、显式开发者模式、撤销、相同版本冲突、不兼容的SDK版本、电源重启后的恢复、历史边界和稳定身份回滚。

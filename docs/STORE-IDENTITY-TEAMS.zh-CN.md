# Store 身份与团队

<!-- doc-locale: zh-CN -->
> [English](STORE-IDENTITY-TEAMS.md) | **简体中文**

S5K 冻结了生产认证边界，并实现了第一个团队管理切片。Store 控制服务器仍然是一个 OAuth 资源服务器；它不存储密码、过钥私有材料、恢复代码或上游 OIDC 令牌。

## 实现的 API 切片

- `GET /v1/teams/{team_id}` 返回调用者的团队和最多 100 名成员；
- `POST /v1/teams/{team_id}/members/{member_id}:set-role` 改变一个角色；
- `POST /v1/teams/{team_id}/members/{member_id}:remove` 不可逆地移除
一个活动或暂停的成员资格；
- `POST /v1/teams/{team_id}/members/{member_id}:suspend` 禁用一个活动成员资格，`:restore` 将一个暂停成员资格恢复为活动成员资格；
- 移除、暂停和恢复只接受空体；
- 角色正好是`owner`, `developer`, `release-manager`, 和 `viewer`;
- 跨团队ID返回`not-found`，从不披露成员数据。

团队阅读需要 `store.teams.read`, `store.teams.write` 或内部 `store.control`。角色或成员状态变更需要当前 `owner` 角色, `store.teams.write` 或 `store.control`，启用双因素认证，并且多因素认证的时间不超过五分钟。操作还需要当前团队的 ETag 和一个幂等性键。

一个 PostgreSQL `SERIALIZABLE` 事务锁定团队和目标成员，并将两者资源版本精确增加一个。角色变更更新角色；移除操作将活跃或暂停的成员状态转换为终端 `removed` 状态，并记录其数据库时间而不删除身份。暂停和恢复操作仅转换 `active -> suspended -> active`；两者都会撤销所有现有目标令牌，因此恢复永远不会复活在暂停期间创建或保留的令牌。所有变更都会附加审计/出箱记录。暂停的成员在团队响应中仍然可见，但不能进行身份验证；移除的成员被隐藏且不能进行身份验证。数据库和服务都保留最后一个活跃的所有者。精确重放返回存储的团队主体和 ETag，而无需其他变更。

## 生产登录边界

生产 Portal 使用服务器端 BFF 和外部 OpenID Connect 提供商：

1. BFF 使用带 PKCE 的授权码流程，并严格限制重定向 URI、issuer、audience、state、
   nonce 和时钟偏差；
2. 提供者拥有账户验证、passkeys/WebAuthn、MFA 注册、恢复、滥用控制和凭证通知；
3. BFF 将不可变的 `(issuer, subject)` 对映射到 Store 成员，并仅创建一个哈希后的、短暂的不透明控制令牌；
4. `mfa_authenticated_unix_seconds` 只有在配置并验证了 MFA 保证声明之后才会被填充；仅凭令牌创建时间不足以证明 MFA。
5. 浏览器只接收一个不透明的`Secure`, `HttpOnly`, `SameSite=Strict`。门户会话 cookie。控制令牌和 OIDC 刷新令牌保留在 BFF 中；写操作也需要同源 CSRF 保护。
6. 门户会话有30分钟的空闲时间和八小时的绝对生命周期。
敏感操作会在五分钟步升窗口结束后强制刷新提供者挑战。

IdP供应商、接受的ACR值、企业联合、账户关联策略和恢复升级必须在登录启用前配置和审核。电子邮件地址是显示/联系数据，绝不是稳定的登录密钥；外部发行人和主题构成身份。

审阅者身份保持为独立的SSO领域。开发团队角色通过此API永远无法授予`store.review`或成为审阅者。

## 数据库约束

- 团队身份不能重新分配或删除；成员身份不能重新分配或物理删除。
- 成员资格从版本1开始生效，仅支持激活/暂停的转换，在移除前，且在移除后变为不可变；
- 每次 Team 或成员 更新都会将其资源版本增加 exactly one；
- 成员电子邮件值被限制长度、修剪和转换为小写；
- MFA 认证时间是可选的、不可变的正数，并且不能晚于令牌创建时间；
- 访问令牌只能转换为失效状态，不能被删除；
- 延迟的最后所有者约束仍然是最终的数据库后备。

现有的令牌从预-S5K 数据迁移而来，无需进行 MFA 认证时间验证，
因此在敏感团队写入时会关闭，直到发出真正的提升令牌为止。

## 验证

PostgreSQL 接收门涵盖有界有序读取，缺失范围、角色和团队隔离，禁用和过时的 MFA，最后所有者保护，过时的 ETag，精确重放，即时目标令牌撤销，暂停/恢复，终端移除，数据库绕过，以及注入的角色/移除/暂停审核失败，证明完全回滚。门户 API 测试将角色和生命周期变化绑定到 ETag/幂等性头；本地门户 UI 暴露暂停/恢复，需要显式移除确认，并禁用对最后活跃所有者的暂停或移除。

提供者中立的账户/链接、邀请、OIDC 回调和门户会话边界在 `STORE-PORTAL-IDENTITY-V1.md` 和 `store-portal-identity-v1.openapi.json` 中冻结。其 PostgreSQL 账户、身份链接、OIDC 交易、会话、邀请和会员绑定状态机通过 SQL 跳过接受实现。专用的门户 BFF 实现了外部 OIDC 登录、回调、仅摘要会话、CSRF、空闲/绝对过期、MFA 级别提升旋转和注销切片，并通过 PostgreSQL 端到端接受实现。邀请创建/列表/检查/取消/接受流程、加密电子邮件工作者传递、精确重放、过期、接受会话旋转和事务回滚也通过实现。身份链接列表/开始/移除、双提供者恢复、依赖会话撤销、会员丢失会话传播和真实的门户浏览器适配器也通过实现。生产电子邮件适配器、提供者 MFA 注册/恢复、IdP 兼容性、审阅者 SSO 和生产滥用控制仍待实现。重新邀请已删除的外部身份需要未来的单独版本化的会员记录设计；此端点从不重新激活已删除的行。

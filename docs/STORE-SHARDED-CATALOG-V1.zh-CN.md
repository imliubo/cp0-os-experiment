# Store 分片目录 v1

<!-- doc-locale: zh-CN -->
> [English](STORE-SHARDED-CATALOG-V1.md) | **简体中文**

S6E 将 Store 发现扩展到超过传统 64 应用程序目录，而无需更改遗留的签名字节或签名域。包含最多 64 个应用程序的一代继续发布 v1-v4 `SignedCatalog` 在 `catalog.json` 路径下。更大的一代在相同路径下发布 `SignedCatalogIndex`，并在 `shards/` 之下发布不可变签名碎片。

## 边界和兼容性

- 一个遗留的目录最多包含64个应用程序和48 KiB；
- 一个根索引包含1-16个描述符，并且最多为48 KiB；
- 每个分片包含 1-64 个应用程序，并且最多为 48 KiB；
- 一个分片包含总共 1-1024 个应用程序，但在下面仅使用其中的 65 个应用程序，当它们的遗留签名编码超过 48 KiB 时。
- 应用程序和分片范围严格按 App ID 排序；
- 设备通过互斥的 `catalog` 和 `catalog_index` 成员来区分两个顶层文档，并拒绝混合或未知字段。

目录、根索引和分片签名使用单独的领域分离符。根签名绑定生成序列和有效性窗口，每个应用程序使用的内容模式、总数、编辑投影、确切类别索引和每个分片URL、SHA-256哈希值、字节长度和App ID范围。每个分片独立签名并重复根序列、内容模式和序号。

## 类别索引

根包含一个条目，对应于每个非空的Store类别。条目及其分片序号严格排序。每个条目绑定该类别的精确应用数量和包含该类别的分片。设备仅在接受所有验证应用重新计算此索引后才接受一个生成。因此，CDN无法添加、删除、移动或重新分类一个应用。

## 发布和设备提交

发布者将每个分片、根、透明对象和公钥写入临时的不可变生成中，同步它，并重命名整个目录。数据库事务记录根快照和每个分片，在任务完成之前。启动恢复在修复`current`之前验证根和精确的分片集。

`cp0-stored` 首先下载并验证根，然后按顺序下载每个分片。它在私有目录中准备完整的版本，并在替换缓存根之前原子性地安装该目录。如果分片失败、缺失、顺序错误、被替换或过大，将保留前一个版本。搜索和类别浏览仅在完整的验证集中进行；安装授权仍然绑定到根序列和精确的应用对象。

透明日志继续提交 `catalog.json`. 对于分片的生成代中，该对象是带符号的根，其描述符通过传递方式绑定所有分片字节。

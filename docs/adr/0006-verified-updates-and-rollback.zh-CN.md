# ADR 0006: 验证的OS更新和回滚

<!-- doc-locale: zh-CN -->
> [English](0006-verified-updates-and-rollback.md) | **简体中文**

- 状态：接受架构；硬件启用延期
- 日期: 2026-07-31

## 上下文

当前的三分区镜像包含一个FAT启动分区，一个ext4下层根分区和一个ext4 `cp0-data` 分区。OverlayFS 保护了下层根分区不受普通运行时写入，但SD卡攻击者可以替换固件配置、内核、initramfs或下层根分区。存储在同一个可变启动分区中的dm-verity根哈希可以检测随机损坏，但不能验证镜像。

系统也没有事务型的操作系统更新器。应用程序商店回滚与内核/根文件系统回滚无关，且不得将其重新使用为操作系统信任根。

## 决策

最终的生产更新设计是一个带签名的A/B系统：

1. 使用单独的启动/根槽对加上现有的共享`cp0-data`分区。更新总是写入不活动的槽位，从不 mutation 运行中的槽位。
2. 使用 dm-verity 保护每个根槽。其根哈希包含在签名的启动元数据中，而不是在独立可变的命令行中。
3. 使用由专用离线OS更新密钥签名的RAUC包。Store密钥
无法授权OS镜像、恢复介质或启动元数据。
4. 标记一个新的插槽为待处理状态，要求使用签名的启动上下文来识别该插槽和释放序列，并加上 compositor/appd/data-mount 健康检查，然后提交。当健康检查仪式未完成时，启动尝试计数器将恢复到之前的插槽。
5. 保持 `cp0-data` 不在插槽替换之外。模式迁移必须与之前的 OS 插槽兼容，或者在新插槽提交之前进行单独可恢复的数据迁移。
6. 保留独立恢复镜像和离线 `CP0 backup v1` 工作流。
   恢复介质不继承在线OS更新密钥。

U-Boot带有签名的FIT镜像是一种候选实现，用于签名启动元数据和回滚状态，而不是一个信任锚点本身。树莓派固件仍然从可变的FAT分区加载U-Boot。因此，U-Boot/FIT签名只有在早期的不可变硬件或固件根验证了第一个可变阶段时才提供真实性。

没有OTP，安全启动密钥或不可逆硬件状态将不会编程到唯一的V0.6测试设备上。硬件使能需要一个一次性电路板或可恢复的供应商程序，确认BCM2710基于CM0的启动路径支持所需的根信任，并且有一个经过验证的密钥丢失恢复过程。

## 被拒绝的快捷方式

- OverlayFS 单独使用：在正常运行期间防止持久写入，但不检测离线修改。
- dm-verity 与未签名的根哈希结合：适用于检测损坏，但不适用于 SD 攻击者的 authenticity 鉴定。
- RAUC 有一个根槽：可以验证一个包但不能保证在断电或内核/用户空间组合不良时恢复。
- U-Boot/FIT 在可变FAT上且没有更早验证的阶段：更改变量的物理信任差距，而不是关闭它。
- 重用Store签名根：将应用程序审核与完整OS控制绑定在一起，并使撤销影响范围无法接受。

## 启用门

实施将在所有这些内容都可以在一次性介质上进行测试，并在必要时使用备用电路板之后进行：

- 根据供应商文档和硬件证据，准确记录 V0.6 ROM/固件的安全启动能力；
- 最终分区大小符合支持的SD卡最低要求，并包含两个完整的OS槽和受限的RAUC临时空间；
- 100 中断更新故障注入周期保留一个可启动槽；
- 无效签名、过时版本、错误的板卡ID和损坏的验证树；所有情况均保持关闭状态；
- 自动回滚在断电时保留 `cp0-data`;
- 更新密钥的轮换、撤销、备份和灾难恢复都已记录并进行了演练；
- 峰值更新内存与512 MB设备预算兼容。

直到这些门通过后，CardputerZero OS 构建物仍为开发或恢复候选。项目不得声称已验证启动或无人值守的事务性 OS 更新。

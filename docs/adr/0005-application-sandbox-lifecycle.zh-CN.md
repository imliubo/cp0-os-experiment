# ADR 0005: 应用沙盒生命周期

<!-- doc-locale: zh-CN -->
> [English](0005-application-sandbox-lifecycle.md) | **简体中文**

- 状态：已接受，进入第3阶段实施
- 日期: 2026-07-30

## 上下文

CardputerZero 应用程序是不受信任的 WASM 模块。WASM 运行时限制了模块的指令和内存访问，但运行时缺陷必须不能暴露宿主文件系统、设备、IPC 端点或另一个应用程序的数据。应用程序还需要一个稳定的标识用于存储、 compositor 策略和权限决策。

目标设备有512 MB RAM，并且只运行一个前台应用。因此，设计必须使用现有的内核和systemd原语，而不能引入容器守护进程。

## 决策

根拥有的`appd`是唯一允许将已安装的包转换为运行应用的组件。其启动顺序是：

1. 加载已安装的清单文件并验证其架构、包签名和不可变包位置。
2. 通过根拥有注册表解析包ID到一个稳定的系统账户名为`cp0-app-N`。调用者不能选择此映射。
3. 解决应用程序的私有存储配额。持久化数据仍然属于`cp0-storaged`，并且不会挂载到应用程序的沙盒中。
4. 启动一个带有内存控制组和进程强化的临时 systemd 单元。
5. 输入一个 bubblewrap 进程ID，挂载，IPC，UTS，cgroup 和 网络命名空间。该包以只读方式在`/app`挂载；`/data`是命名空间本地的且为空。
6. 执行静态的、根拥有的App Runtime。Runtime加载验证过的WASM/AOT 入口点，并仅接收预先打开的Wayland和能力代理服务通道。

没有主机 `/usr`, `/home`, `/run`, 系统 D-Bus, 设备节点或任意 Unix 套接字可见。Bubblewrap 是一个命名空间构造器，而不是应用程序兼容环境。第三方原生可执行文件仍然不支持。

初始实现会发出一个结构化的 `SandboxPlan`. 只有在测试证明计划中的每一个路径、账户、包和描述符都源自可信状态之后，才会添加执行。命令始终作为参数数组传递；shell 解析不在启动路径中。

Seccomp 应用在 Bubblewrap 构造命名空间之后，因此 App Runtime 无法保留设置期间所需的挂载和命名空间系统调用。在 `appd` 可以启动生产应用之前，需要 runtime 允许列表、继承描述符协议、账户注册表和配额后端。

Wayland 运行时目录从不挂载，应用程序账号从不加入其拥有组。systemd PID 1 打开配置的 compositor 套接字，并将连接的流作为描述符 3 传递。固定下来的 bubblewrap 执行路径为它的子进程保留了该继承描述符，并且 Runtime 拒绝任何其他显示描述符合约。

`ProtectKernelTunables=yes` 不能应用于外部瞬态单元：其 systemd `/proc/sys` 挂载防止未特权用户命名空间挂载 bubblewrap 所需的私有 `/proc`。应用程序仍然无法更改主机调优项，因为它处于非初始用户命名空间，并且运行时 seccomp 策略拒绝 `open`、`openat` 以及所有挂载系统调用。

## 后果

- 一个被攻破的WASM运行时仍然受一个唯一的主机UID、命名空间、cgroup限制、一个空的能力集和seccomp的约束。
- 应用程序不能通过知道路径或套接字名称来进行通信。意图和硬件访问必须通过能力代理服务进行。
- 一个稳定的账户注册表必须在升级过程中存活，并且在该应用的数据或权限记录仍然存在时，绝不能回收 UID。
- 直接执行生成的计划只是一个诊断功能。生产启动总是会重新验证安装的包和注册表，路径为`appd`.

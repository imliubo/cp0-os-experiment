# ADR 0007: 第一次启动的身份和配置

<!-- doc-locale: zh-CN -->
> [English](0007-first-boot-identity-and-provisioning.md) | **简体中文**

- 状态：已接受；在新介质接受门后实现
- 日期: 2026-08-02

## 上下文

当前开发镜像需要构建时的用户名/密码，而生产访问配置文件锁定一个固定的`pi`账号并禁用所有登录路径。后者移除了可重用的密码，但不满足产品要求，即分发镜像中不应包含固定的用户名，而是让其所有者完全在320x170 LCD上配置身份和网络。

底层根是不可变的，只有 `cp0-data` 上的选定路径在持续。因此，首次启动实现不能安全地仅在 OverlayFS 上层层中突变 `/etc/passwd`。设置还处理密码和 Wi-Fi 凭据，所以它不能是不可信的 SDK 应用程序或接收根权限。

## 决策

1. 产品镜像中不含任何人类账户。pi-gen 可能会使用一个临时 `cp0-build` 阶段身份，但导出会移除该账户、家目录、组以及所有拥有的残留物。挂载镜像闸门强制执行没有交互普通 UID、密码哈希和授权密钥。
2. 所有者在本地创建并存储在`cp0-data`上的专用extrausers NSS/PAM数据库中。不可变`/etc`继续只拥有root和非交互式系统/服务身份。所有者范围是`1000-1999`；应用程序UID保持不变`20000+`。
3. 现有的受信任 System Shell 拥有 Setup UI。而在设置不完整时，
   compositor 会阻止 Home、Tasks 和普通应用变为 active。
4. 一个新的仅根文件系统 `cp0-provisiond` 拥有账户、区域、NetworkManager 和 SSH 变化。它仅从精确的 `cp0-shell` 对等 UID 接受有界版本化的 Unix 协议，并且永远不会返回密钥。
5. 持久且非秘密的配置状态原子地存储在`cp0-data`上。每一步都是幂等的，并且`COMPLETE`最后写入。跨对象的分歧进入`REPAIR_REQUIRED`；它从不默默地绕过设置、删除数据或创建另一个所有者。
6. 网络完成意味着成功的以太网配置、保存的Wi-Fi配置文件或显式的离线选择。当前的链路状态并不控制将来进入设置的行为。
7. SSH 默认是关闭的，并且是通过标记控制而不是永久屏蔽。启用它需要显式的 Setup/Settings 决定，root 登录仍然禁用，并且只有动态所有者组可以认证。
8. 默认情况下，所有者没有 sudo 权限。稍后可能授予一个单独审计的受限管理角色。

详细的UI、存储、密钥处理和测试合同在 `docs/FIRST-BOOT-PROVISIONING.md` 中。

## 后果

- 量产镜像不再包含通用的构建时登录路径。Recovery 仍是单独标记的物理维护制品。
- 镜像增加了 extrausers/PAM 集成、小型特权 daemon，以及 OS 回滚必须保留的持久 Owner home/identity schema。
- System Shell 负责一个额外的可信状态，但不会获得 root 权限或直接访问凭证文件。
- 设置完成后网络丢失是正常设置条件，不会将所有者困在启动循环中。
- 恢复出厂设置必须在一次操作中清除身份、home、网络 profile、SSH 材料和完成状态。
- 公钥注册需要单独设计的导入和指纹界面；
它不能通过看不见的启动分区魔法近似实现。

## 被拒绝的替代方案

- **发送锁定固定用户**：移除密码访问但仍然嵌入一个人类身份，并且不能支持用户选择的凭证。
- **持久化所有`/etc`或账户文件**：将可变数据与服务账户耦合，并使A/B更新和回滚容易发生冲突。
- 将 `useradd` 运行到 OverlayFS 中：当叠加/数据状态变化时会丢失或分割身份，并且无法提供更新稳定的合同。
- 将“Make Setup an SDK application”设置为SDK应用程序：赋予不可信应用程序机器身份/网络权限，并允许UI/焦点模糊。
- **以 root 身份运行整个 Shell**：不必要的扩展了渲染、输入和元数据解析的信任攻击表面积。
- **重新设置设备以应对离线情况**：使暂时的网络故障成为设备可用性故障，并将配置与连接性混淆。
- **启用SSH或sudo自动**: 创建了一个与产品安全模型相反的未记录的远程或本地权限路径。

## 实施和启用门禁

产品负责人于 2026-08-02 批准全部六项决策。有界协议、认证守护进程、extrausers 身份、
`cp0-data-layout-v2`、marker 控制的 SSH 和可信 Setup UI 均已实现。宿主机 `make check`、
Linux/arm64 `SOCK_SEQPACKET`/`SO_PEERCRED`、PAM/NSS 和完整 compositor 构建检查均通过。
任何量产声明或设备部署前，仍必须构建新的量产镜像并完成 V0.6 空白介质验收。

# Phase 6H: 验证更新的基础工作

> [English](PHASE6H-VERIFIED-UPDATE-GROUNDWORK.md) | **简体中文**

## 范围

此阶段实现ADR 0006中无需更改活动CM0启动链或编写一次性介质即可证明的部分。它故意不在量产镜像中启用操作系统更新器。

本地实现包含：

- `cp0-os-update`, 一个严格的解析器和策略库，用于认证的OS发布元数据和A/B启动状态；
- `schemas/os-release-v1.schema.json`, 发布工具合约；
- `verify-os-release-artifacts.sh`, 将根文件系统、dm-verity 哈希树和签名的 FIT 字节绑定到元数据，然后调用`veritysetup verify`；
- 确定性测试对于过时的发布、错误的板卡ID、不兼容的数据布局、不完整的健康检查、三次失败的启动和100次连续中断的更新。

固定的板卡ID是`cardputerzero-cm0-v0.6`。发布序列是单调的，并且与应用Store版本无关。一个发布包含根文件系统的哈希值和大小、单独的可信度哈希树和FIT、以及可信度根哈希、盐、数据块计数和FIT配置名称。SemVer版本中的构建元数据被拒绝，因此一个可见版本不能描述不同的OS字节。

## 更新仪式

最终的RAUC集成必须按以下步骤进行：

1. 使用专用的离线OS更新根验证RAUC CMS签名。
2. 解析有界发布元数据，并拒绝错误的板卡、过时的序列或不兼容的`cp0-data`布局。
3. 写入仅不活跃根，验证树和启动/FIT插槽。
4. 重新读取每个制品，比较其认证大小和SHA-256，并在完整根文件系统上运行`veritysetup verify`。
5. 验证签名的FIT配置是否绑定内核、initramfs、DTB，
   dm-verity 根文件系统哈希和槽身份，然后再使槽可启动。
6. 将不活跃的插槽阶段化三次，并持久化写入两个完整状态记录。
7. 在每次传输到待用槽位之前，减少其剩余尝试次数，然后写入并重读新状态，最后启动。因此，在选择后发生电源中断会消耗一次尝试次数而不是创建无限重试循环。
8. 仅当签名启动上下文报告确切的待处理插槽和释放序列以及 compositor、appd 和 `cp0-data` 挂载健康都成功时，才确认插槽。在三次未确认尝试之后进行第四次选择，清除待处理状态并启动最后一个确认的插槽。

每个状态记录包含一个生成时间和一个域分离的SHA-256校验和。在恢复时，启动选择器会选择最高的有效生成时间；两个具有相同生成时间和不同有效记录会失效。一个损坏或不完整的副本可以被忽略。校验和只能检测到意外损坏和不完整的写入。它不是MAC、签名、防重放计数器或物理攻击防护。

记录验证也会拒绝启动选择器无法生成的状态机组合：零确认序列、超出 JSON 精确整数范围的生成、带有记录尝试的三个尝试待处理插槽、缺少匹配尝试插槽的待处理插槽递减、或最后一个尝试与确认插槽不同的非待处理状态。即使一个格式错误的状态携带内部正确的校验和，这些检查也适用。

## 本地验证

运行策略并回滚测试：

```sh
cargo test -p cp0-os-update
./tests/test-os-update-profile.sh
```

使用Linux verity构建生成的文件，运行真实的离线门：

```sh
./scripts/verify-os-release-artifacts.sh \
  release.json rootfs.img rootfs.verity slot.itb
```

验证器需要 `jq`，一个SHA-256实现和 `veritysetup`。通过意味着字节与已认证的元数据匹配，并且验证树内部有效。它不验证RAUC CMS、FIT签名或授权任何封套的关键链。

## 延迟硬件边界

当前的产品和恢复镜像保留其现有的三分区布局，可变的树莓派固件/FAT启动路径和OverlayFS底层根目录。它们不包含RAUC服务、启动选择器、dm-verity映射、U-Boot或签名的FIT。在这一阶段，它们的安全声明没有任何变化。

在集成之前，一次性介质和备用电路板必须建立确切的CM0固件到U-Boot信任路径，启动分区/布局约束，冗余状态存储，FIT算法和密钥注入程序。然后，硬件验收必须涵盖无效的CMS/FIT签名，过时的序列号，错误的电路板ID，损坏的根/哈希树，100次断电，自动回退，`cp0-data`保留，密钥轮换和512 MB峰值内存预算。唯一V0.6设备上不得写入任何OTP或不可逆的密钥状态。

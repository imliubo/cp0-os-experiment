# Store 搜索 隐私 v1

<!-- doc-locale: zh-CN -->
> [English](STORE-SEARCH-PRIVACY-V1.md) | **简体中文**

S8D 将 Store 搜索冻结为设备上的操作。查询仅从受信任的 System Shell 通过本地 Unix 套接字传输到 `cp0-stored`。守护进程在内存中按已验证的 Catalog 排序应用程序，并返回一页结果。搜索永远不会触发 Catalog、媒体、包或指标的网络流量。

## 数据边界

- 查询不会写入守护进程状态、指标状态、日志或目录缓存文件。
- Shell 在其过程拥有的 UI 结构中最多保存四个最近的查询。当 Shell 重启时，这些查询会被丢失，并且永远不会写入磁盘。
- 响应只会回显与查询完全相同的请求以绑定本地响应。严格的IPC解码器拒绝不同的查询或页面。
- 聚合指标仅包含精确的应用版本安装、启动和崩溃计数器。它们严格的数据结构拒绝了`query`、`experiment_id`以及其他所有未知字段。
- 启用应用指标并不授予搜索收集或搜索实验的同意。

在v1中没有搜索实验协议或端点。添加一个需要一个单独的默认关闭同意目的、显式的字段允许列表、固定的保留和删除计划、一个与App Metrics独立的策略开关，以及在量产部署前的隐私/安全审批。在新合同存在之前，搜索数据不能离开设备。

## 验证

daemon 测试使用了一个网络实现，每当执行目录、资源、包或指标操作时都会触发 panic，然后执行搜索并验证指标状态和缓存内容没有变化。指标测试注入了禁止的查询和实验字段，并要求严格解码失败。System Shell 测试将最近的查询保留在新初始化的 UI 结构中；该状态没有持久化 API。

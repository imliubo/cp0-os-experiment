## 测试身份

- 日期: 2026-08-02, 亚洲/上海
- 设备: CardputerZero V0.6, Raspberry Pi CM0, 512 MiB RAM
- 设备地址: `192.168.31.121`, 有线测试连接
- 显示: 内部LCD, `320x170@30`
- 部署：易失性RAM覆盖二进制文件和服务；不闪存镜像且不重启
- Linux `uinput` 键盘使用与物理键盘相同的 Weston/libinput 和可信 compositor 路径
- 视觉证据：可信 compositor 截图 API，精确 320x170 PNG 输出

状态意义：

- `PASS`: 在V0.6设备上执行并通过UI以及适用时通过后台服务、硬件读回或状态转换进行观察。
- `BLOCKED`: 实现路径存在，但所需的外部配置缺失。
- `NOT SUPPORTED`: V0.6产品的功能故意不可用，并且UI正确地报告了这一点。
- `NOT EXECUTED`: 控制和确认界面通过了测试，但执行破坏性或持久性操作的提交超出了此次测试的范围。

## 结果

Home 系壳和所有五个系统应用完成了可用的功能矩阵。设备和网络不再显示错误，设置不再报告可用的 Wi-Fi/显示/音频控制为不可用，并且所有支持的设置完成了一次状态变化/读取/恢复周期。

在运行过程中发现并修复了一个唯一的设备专用缺陷。`cp0-appd` 使用了`systemctl wait`子命令，而在设备的Debian systemd版本中该子命令不可用。应用程序执行正常，但运行时监控器每5秒记录一次错误，并可能导致会话清理延迟。现在监控器每250毫秒轮询`systemctl is-active`。主机测试、AArch64发布构建和设备启动/停止验证均通过，没有新的等待错误。

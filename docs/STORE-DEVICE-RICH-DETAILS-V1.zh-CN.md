# 存储设备丰富详情 v1

<!-- doc-locale: zh-CN -->
> [English](STORE-DEVICE-RICH-DETAILS-V1.md) | **简体中文**

S6D 将签名 Catalog v3 的媒体层次结构连接到 320x170 System Shell，同时不暴露私有缓存路径，也不把图像字节放入有界 JSON 帧。

## IPC 合约

Store 协议仍然使用换行符分隔的 JSON，并且帧限制为 64 KiB。
两个有界命令扩展协议版本 1：

- `details` 返回绑定目录的应用/版本、开发者、类别、年龄评级、隐私/支持链接、描述、发布说明和屏幕截图数量。签名详细信息源仍限制在16 KiB。
- `media` 选择图标或一个屏幕截图索引。成功响应绑定应用 ID、版本、媒体类型、索引、SHA-256、编码字节长度和尺寸，并携带一个只读描述符 `SCM_RIGHTS`。

错误和非媒体响应不得携带描述符。媒体成功响应必须携带恰好一个描述符。接收方拒绝缺少、重复或截断的控制数据，启用`FD_CLOEXEC`，要求读-only常规文件，并在解码前检查描述符长度与响应的匹配。缓存文件系统路径从不跨越IPC边界。

`cp0-stored` 下载或重用内容寻址对象，验证其签名摘要、长度和 PNG 结构，然后使用 `O_NOFOLLOW | O_CLOEXEC` 打开最终的 `0600` iNode。响应元数据来自相同的签名目录/详细信息描述符。

## Shell 渲染

Store 详细视图有五个前台页面：

1. 图标, 身份, 开发者/类别/年龄和安装状态;
2. 换行显示，可垂直滚动的描述；
3. 一次完整 320:170 截图，并带有边界索引导航；
4. 请求的权限和更新时权限的添加；
5. 垂直滚动的分词包裹式 发行说明

C客户端需要每个细节/媒体响应匹配UI当前选择的app ID和版本。libpng仅在描述符和维度检查之后解码为固定XRGB/alpha像素缓冲区。`struct cp0_ui`保持在64 KiB以下；Shell拥有一个48x48图标缓冲区和一个320x170屏幕截图缓冲区，总计约222 KiB，在其现有的32 MiB服务限制之下。

目录/列表/安装行为在丰富细节或媒体失败时仍然可用。因此，遗留目录 v1/v2 条目保留现有的基本概述，并显示一个不可用的丰富细节状态，而不是削弱验证。

## 验证

Rust 测试覆盖严格的请求/响应验证、描述符传输、只读媒体打开和缓存字节身份。C 测试覆盖额外字段、应用/版本/索引/维度不匹配、截断或重复描述符、`FD_CLOEXEC`、真实 PNG 解码和固定像素输出。System Shell 测试覆盖所有五个页面、详细滚动、屏幕截图导航、陈旧 Catalog 安装阻塞和 64 KiB UI 状态预算，带有像素快照。

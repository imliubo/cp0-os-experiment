# Store Workforce Identity v1

<!-- doc-locale: zh-CN -->
> [English](STORE-WORKFORCE-IDENTITY-V1.md) | **简体中文**

这份文档冻结了审查控制台和Store操作共享的提供者中立的身份边界。它定义了BFF合同和Store控制面持久性不变量；它不选择或模拟生产身份提供者。

## 信任边界

审查和操作观众永远不会共享浏览器会话、cookie、回调路径或控制令牌。审查使用 `__Host-cp0_review` 并且和 `review` 观众. 操作使用
`__Host-cp0_operations` 并且和 `operations` 观众。两个饼干都是 `Secure`, `HttpOnly`,
`SameSite=Strict`, 有 `Path=/`，而且没有任何 `Domain` 属性

BFF 是唯一的 OIDC 客户端。它从不将 ID 令牌、提供程序访问令牌或刷新令牌转发给浏览器应用或 Store 控制 API。浏览器仅接收一个随机会话 cookie，只有在明确请求时，才会收到一个有效期较短的 Store 控制令牌，其精确受众和范围与此相关。

## 登录和会话

1. BFF 解析配置的提供者密钥并创建一次性的 OIDC 交易。它存储 `state` 和 `nonce` 的 SHA-256 散列值、加密的 PKCE 验证器字节、提供者配置散列值、受众和意图。该交易在十分钟内失效，并在消耗或过期后终止。
2. 回调验证确切的发行者、客户端受众、签名、`state`、`nonce`、PKCE，
   提供商配置摘要和MFA证据。重定向目标是固定同源路径，
   从不包含请求参数。
3. 经过规范化后的颁发者和主体通过HMAC-SHA-256进行加密后再持久化。原始OIDC主体、ID令牌和提供者令牌从未存储在Store表或日志中。
4. 一个活跃的身份链接必须解析为匹配受众中的一个活跃且启用双因素认证的审核员或操作员。一个主体最多只有一个活跃的工作force链接。
5. 一个会话的闲置生命周期为15分钟，绝对生命周期为8小时。它只存储其cookie和CSRF密钥的SHA-256摘要。活动可以将闲置截止时间向前移动，但永远无法延长绝对截止时间或恢复终端会话。

MFA 证据必须来自一个提供者配置，其接受的 `acr`、`amr` 和最大 `auth_time` 年龄是部署策略。仅仅有一个本地 `two_factor_enabled` 标志并不能证明当前 OIDC 交易执行了 MFA。

## 控制令牌

这些令牌端点需要特定于受众的会话cookie `X-CSRF-Token` 和一个 `Idempotency-Key`. 响应使用 `Cache-Control: no-store`. 仅审查问题 `store.review`.
操作问题会根据当前操作员角色精确使用 `store.editorial` 或 `store.moderation`。

控制令牌是不透明的，并且是从其会话、受众、范围和幂等性密钥派生的目的键，因此精确重放可以重建相同的持有者而无需存储它。仅存储其SHA-256摘要。它绑定到一个会话，并且有效时间不超过五分钟。其过期时间不能超过会话空闲超时或绝对超时。每次Store认证查询都会重新检查以下内容，而不仅仅是信任发行：

- token摘要、有效期和撤销状态；
- 活跃会话加上当前空闲时间和绝对截止时间；
- 活跃身份链接
- 精确的 Review 或 Operations 用户群体；
- 精确的审核员或操作员绑定到both link和token；
- token 创建在会话创建时或之后，并且最多五分钟。

遗留的未绑定测试/管理令牌在迁移期间保持模式兼容。生产浏览器流量必须使用会话绑定令牌；移除可为空的兼容路径需要单独的凭据迁移和部署门。

## 即时撤销

注销操作最终撤销会话并立即撤销所有绑定的控制令牌。撤销身份链接会最终撤销该链接中的所有活动会话，进而撤销其令牌。暂停审阅者或操作员也会执行相同的会话到令牌级联操作。身份验证还会检查活动主体、会话和链接行，因此失败或延迟的工作者从不成为安全边界。

身份链接、会话和OIDC交易是后缀保留的状态机：终端行不能恢复或删除。访问令牌只能从未撤销状态转换到已撤销状态。数据库触发器在与其父撤销操作相同的事务中强制执行每个转换。

## 浏览器和部署控制

- 审核和操作是分开的起源，具有固定的回调允许列表，并且没有宽松的CORS。
- 每个经过cookie认证的mutation都需要匹配的CSRF密钥，并在解析body之前拒绝跨域请求。
- 认证和回调响应是受限的，使用`no-store`，并且永远不要反映提供者错误、声明、令牌或秘密。
- 主题-HMAC、PKCE 加密、CSRF、nonce 和控制-token 密钥是独立的版本化秘密，不在 PostgreSQL 外面。轮转需要重叠程序和独立审计证据。
- 登录、回调、令牌颁发、注销、链接撤销和主体暂停会发出带有边界限制的审计事件，无需使用cookie、CSRF、OIDC或bearer密钥。
- 提供者元数据、签名密钥、颁发者白名单、多因素认证策略、时钟偏差和紧急禁用控制是生产配置，不是浏览器输入。

## 交付的证据和剩余的门

迁移 `0027_workforce_identity_foundation.sql` 和
`0028_workforce_bff_operations.sql` 实现了单独的链接、会话、OIDC 交易，
会话绑定的令牌、幂等的发放/注销记录和同步撤销。
`cp0-store-workforce-server` 实现了生产形状的 BFF 路由和严格的双源配置。
PostgreSQL 接受测试涵盖了有效的审核和操作身份验证、受众不符、令牌生命周期/重放、控制 API 使用、范围授权、所有三个撤销路径、终端不可变性、无密钥审核证据和撤销后的 HTTP 拒绝。审核控制台和 Store 操作包括严格的内存中会话/令牌适配器。OpenAPI 合同是 `schemas/store-workforce-identity-v1.openapi.json`；部署细节在 `STORE-WORKFORCE-SERVER.md` 中。

生产 IdP/JWKS 配置、管理秘密存储、员工账户分配以及实时访问撤销练习仍然是部署关卡。没有假提供者或本地接受数据库作为生产 SSO 证据。

## 测试身份

- 日期: 2026-08-03, 亚洲/上海
- 设备: CardputerZero V0.6, Raspberry Pi CM0, 512 MiB RAM
- 设备地址: `192.168.20.66`, 有线测试连接
- 显示验证：操作员观察；没有本地摄像头可用
- 基础介质：早期量产候选版本，带有一启动易失性 `cp0-provisiond` 热更新
- 候选源：`d12383c` (`Support hot updates from noexec runtime`)

状态意义：

- `PASS`: 在V0.6设备上执行，并带有服务或持久状态回读。
- `FIXED / IMAGE PENDING`：设备暴露了缺陷，源代码修复和主机回归测试通过了，但修订后的路径仍需要进行一次全新的介质运行。
- `NOT EXECUTED`: 需要物理重启或新烧录的镜像。

## 结果

设备名称故障被重现并追踪到Raspberry Pi OS布局 `/etc/default/locale -> ../locale.conf`。配置代理拒绝了目标，因为这是一个符号链接。修正后的实现原子地替换链接本身，从不跟踪或修改其原来的目標。在修正后的AArch64代理热更新后，设备完成了区域、所有者、密码、有线网络和SSH同意步骤，并达到审核阶段。

最终提交暴露了一个第二个生产布局缺陷。`ssh.service`受完成标记和SSH同意的双重控制，但旧交易在写入完成标记之前就开始了SSH。因此systemd跳过了启动，然后停止了维护SSH。现在源代码会写入`COMMITTING`，安装完成标记，激活SSH，然后才写入`COMPLETE`。恢复测试涵盖了标记交易两侧的中断情况。这种修订后的顺序包含在新图像中，但在该图像被烧录并完成一次之前，不能声称这是设备通过。

## 缺陷修复

1. 安全的常规区域符号链接现在会原子地替换而不是被拒绝。一个回归测试证明旧的目标保持不变。
2. 最终提交现在在启动受控SSH之前发布完成标记，同时保留`COMMITTING`崩溃恢复。
3. One-boot 热更新在 `/run` 下不再依赖于可执行文件在 `noexec` 挂载上可用。验证需要一个常规的、非符号链接的、非空的、根用户拥有的模式 `0700` 文件，在复制到可执行文件易失性覆盖层之前。

## 保持新鲜媒体接受

1. 在没有热更新的情况下，烧录候选镜像并完成所有欢迎页面的设置。
2. 确认按住 Shift 可在物理键盘上产生大写输入。
3. 独立地练习以太网、Wi-Fi和离线设置路径。
4. 通过SSH连接，验证所有者身份认证，并证明根和应用身份被拒绝。
5. 冷启动SSH关闭，并证明不存在监听器或可重用访问路径。
6. 在每个持久阶段和最终提交的两侧中断电源，然后确认无需第二个所有者即可确定性恢复。
7. 确认完成状态转换到主页，并且在接下来的十次冷启动后不重新打开设置。
